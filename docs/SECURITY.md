# Security and limits

Passwords use Node scrypt with random salts and constant-time comparison. API responses omit hashes. Random 256-bit session secrets use HTTP-only SameSite=Lax cookies; only SHA-256 session digests are stored. Sessions expire after seven days; production cookies are Secure. Logout revokes the session. Reset and local verification tokens are hashed, single-use and valid 15 minutes. External email delivery is not connected. Avatar uploads accept only bounded PNG/JPEG/WebP data URIs; the client crops and resizes to 128 pixels.

Mutations require the configured Origin and, when authenticated, a session CSRF token. Express uses Helmet, rate limits, size-limited JSON and Zod validation. Registration ignores supplied privilege/XP fields and always assigns USER. Frontend role guards are backed by independent ADMIN/SUPER_ADMIN/BUSINESS_ADMIN endpoint checks. Only SUPER_ADMIN can grant roles or manage privileged accounts. Ordinary admins can suspend/restore riders; self-modification is blocked. Access changes revoke sessions and socket connections. A local provisioning command creates a separate super administrator without public privileged registration.

Transactions, conditional bike updates, expected simulation steps and unique redemption/wallet/pass references protect tested concurrency/idempotency paths. The server generates demo points/timestamps and rejects duplicates/implausible movement. It does not claim real GPS cheating prevention. Daily ride-XP/influence caps and repeated-territory cooldowns apply. Influence decay remains planned. Pass purchases capture price/discount terms, never charge a real card and never renew automatically.

Admin fleet/station/mission changes and issue resolution are audited. No audit editing endpoint exists. Complete future destructive-action coverage and append-only storage controls need further work.

Only public active rider profiles appear in leaderboards and public profile pages. Shared profiles contain name, XP, team and achievement history; they exclude email, wallet, routes and live location. Territory controllers and contribution names with private profiles are masked. User data/route records are scoped to the authenticated viewer. Organization membership invitations require rider acceptance. Business admins receive only their organization’s aggregates and scoped sponsor data, never individual routes or health estimates. CSVs require admin access; exports exclude personal routes and protect spreadsheet cells against formula injection. Feedback inbox access is restricted to admins.

Socket handshakes verify active accounts, sessions and CSRF; expiry disconnects them. User rooms allow immediate revocation on logout, reset and access changes. Broadcasts contain only a refresh timestamp. Multi-server synchronization remains unverified. Keep `.env` and demo databases private; production seeding/demo sign-in/credit/rental adapters are blocked.

The dependency audit initially found Prisma’s transitive deepmerge-ts advisory. A patched 8.x override was installed and verified with Prisma generation/migrations/tests. npm reported zero known vulnerabilities after the override. This is point-in-time evidence, not a guarantee.
